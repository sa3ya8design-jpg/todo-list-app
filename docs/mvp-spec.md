# MVP仕様書（案件管理版）

## 1. 概要

### コンセプト

> 最短で入力し、今やるべきことだけに集中できる個人向け案件管理ツール

単なるToDoリストではなく、案件（受託業務など）ごとに作業工程・進捗ステータス・受注金額を管理し、抜け漏れを防ぐ。
出先で修正依頼や確認事項が入った場合も、メモ感覚でタスクとして即入力できることを重視する。

本仕様では「案件」と「プロジェクト」は同義とする。UI表記は従来どおり「プロジェクト」を用いる。

---

# 2. 技術構成

- フロントエンド：Streamlit（Python）
- バックエンド：Python（Streamlitアプリ内で完結）
- データ保存：Google スプレッドシート（projects / tasks / process_steps の3ワークシート）
  - 認証はサービスアカウント方式（公開サーバーでも動作する）
  - スプレッドシートIDと鍵は `.streamlit/secrets.toml` に設定する
    （公開時はホスティング側のSecrets設定に同じ内容を入れる）
  - Sheets APIの遅延対策として、読み取りは60秒キャッシュし書き込み時に破棄する
- 認証：なし（個人利用の単一ユーザー前提のためMVP対象外）

# 4. 案件ステータス

ステータスは以下の5段階とする。

> 提案中 → 受注済 → 作業中 → 請求済 → 完了

- 「完了」もステータス値の1つとする。完了フラグは別途持たず、ステータスが「完了」の案件が
  「完了プロジェクト」一覧に表示される（ステータスと完了フラグを二重管理しない）
- 「完了にする」＝ステータスを「完了」に変更すること
- 「進行中に戻す」はステータスを1段階前の「請求済」に戻す（その後は詳細画面のセレクトで自由に変更できる）
- ステータス変更はプロジェクト詳細画面のセレクトボックスで即時反映する（保存ボタン不要・1操作）
- 新規作成時の初期値は「提案中」
- どのステータスからでも完了にできる。失注した案件も完了へ移して運用する（失注専用ステータスは次フェーズで検討）

---

# 5. 案件の種類

以下の4種から選択する（必須）。

- デザイン
- AIシステム開発
- 古着物販
- その他

種類は工程チェックリストのデフォルト選択に使う。作成後に変更しても既存タスクは変化しない。

---

# 6. 受注金額

- 受注金額（税込・円）のみを管理する。任意入力
- 表示場所：プロジェクト詳細のヘッダー、および作成・編集モーダル
- サイドバー・プロジェクト一覧・ホームには表示しない
- 入金日・残金・入金管理は次フェーズとする

---

# 7. 工程テンプレート

案件の種類ごとに典型的な作業工程が決まっているため、新規作成時に選択するだけでタスクとして投入できるようにする。

## 仕組み

- 工程は全種類共通の「工程マスタ」として1つのリストで管理する
- 種類ごとに「デフォルトでONにする工程」を持つ
- 新規プロジェクト作成モーダルでは、選択した種類のデフォルトがONになった工程チェックリストを表示し、
  ONの工程が上から順にタスクとして投入される（優先度：中、期限：なし）
- 投入後の案件ごとの調整は、通常のタスク追加・削除で行う（案件別カスタムテンプレートは持たない）

## 初期の工程マスタ

ヒアリング / サイトマップ / 見積もり / 提案書 / ライティング / ワイヤーフレーム / デザイン / 実装 / 設定 / リサーチ

デフォルトON（初期値・設定画面で変更可能）：

- デザイン：ヒアリング、サイトマップ、見積もり、提案書、ワイヤーフレーム、デザイン
- AIシステム開発：ヒアリング、見積もり、提案書、実装、設定
- 古着物販：リサーチ
- その他：なし

## 編集

「工程設定」画面で以下を編集できる。

- 工程の追加・名前変更・削除・並び替え
- 種類ごとのデフォルトON/OFF

# 8. 画面一覧

MVPでは以下の画面を実装する。

1. ホーム
2. プロジェクト一覧
3. プロジェクト詳細
4. 完了プロジェクト一覧（アーカイブ）
5. 工程設定

サイドバーには画面ナビゲーションに加え、進行中のプロジェクト一覧を表示する。
各プロジェクトにはステータスをテキストバッジで添え、一目で進捗が分かるようにする（金額は表示しない）。
クリックでそのプロジェクト詳細へ移動する。

※ログイン画面は個人利用の単一ユーザー前提のためMVP対象外とする。

モーダル

- タスク作成・編集
- プロジェクト作成・編集

---

# 9. ホーム画面

役割

未完了タスクの中から「今やるべきこと」を判断する画面。従来どおり全案件の未完了タスクを表示し、
案件カードやステータスは置かない（案件の進捗はサイドバーで確認する）。

## 表示対象

未完了タスクのみ。

タスク行には、どのプロジェクトのタスクか分かるように
プロジェクト名（カラー付き）を表示する。

## 表示順

1. 優先度（高→中→低）
2. 期限
3. 作成日時

## グループ

表示順は以下とする。

- 期限切れ
- 今日
- 明日
- 今週
- 今月
- それ以降
- 期限なし

タスクが存在しないグループは表示しない。

## 今日のタスクが0件の場合

以下のメッセージを表示する。

> 今日のタスクはありません

## 完了したタスク

画面下部に

> 完了したタスク（件数）

を折りたたみ表示する。誤って完了にしたタスクをここからすぐ未完了へ戻せる。

# 10. プロジェクト一覧

表示内容

- プロジェクトカラー
- ステータス（テキストバッジ）

表示しないもの

- 未完了件数

# 11. プロジェクト詳細

ヘッダーに以下を表示する。

- プロジェクト名・カラー
- ステータス（セレクトボックス。変更すると即時保存）
- 種類
- 受注金額（未入力なら非表示）

表示対象

そのプロジェクトの未完了タスク。

一覧表示項目

- タイトル
- 優先度
- 期限

メモ本文は一覧に表示しない。

画面下部に

> 完了したタスク（件数）

を折りたたみ表示する。

展開すると完了タスク一覧を表示し、未完了へ戻せる。

# 12. タスク

## 必須項目

- タイトル

## 任意項目

- プロジェクト
- 期限
- メモ

## 優先度

選択肢

- 高
- 中
- 低

初期値は「中」。

---

# 13. タスク編集

編集はモーダルで行う。

画面遷移はしない。

## 保存

「保存」ボタンで保存し、モーダルを閉じる。

- 自動保存は行わない
  （自動保存だと保存されたか分かりづらく、結局「閉じる」操作も必要になるため。
  「保存」ボタンなら保存と閉じるを1クリックで兼ねられる）
- 「キャンセル」で保存せずに閉じる
- タイトル未入力で保存した場合はエラーを表示する

プロジェクト作成・編集モーダルも同じ方式とする。

---

# 14. タスク操作

| 操作         | 動作     |
| ---------- | ------ |
| チェックボックス   | 完了     |
| タスクをタップ    | 編集モーダル |
| 「延期」ボタン    | 延期     |
| 編集モーダルの「削除」 | 削除（確認あり） |

完了時はトースト通知で「完了しました」と知らせ、戻し方（『完了したタスク』）を案内する。

※スワイプ操作はStreamlit標準機能では実現できないため、「延期」ボタンに置き換える。
※「完了」はチェックボックスと重複するため、ボタンは追加せずチェックボックスのみとする。

延期メニュー

- 明日
- 今週末
- 来週
- 日付選択

---

# 15. プロジェクト作成・編集

保持情報

- 名前
- カラー
- 種類
- 受注金額（任意）

カラーは8色のプリセット（レッド・オレンジ・イエロー・グリーン・ブルー・パープル・ブラウン・グレー）から選択する。
自由なカラーコード入力は行わない。

作成モーダルでは上記に加えて工程チェックリストを表示する（7章参照）。
編集モーダルに工程チェックリストは出さない（タスク追加・削除で調整する）。
ステータスは編集モーダルではなく詳細画面のセレクトで変更する（二重管理しない）。

対応機能

- 作成
- 編集
- 完了（アーカイブ）
- 削除（中のタスクごと削除。確認あり）

サブプロジェクトやグループ機能は実装しない。

---

# 16. 完了プロジェクト（アーカイブ）

終わったプロジェクトは「完了プロジェクト」へ移動する（実体はステータス「完了」の案件一覧）。
UI上の表記は「アーカイブ」ではなく「完了プロジェクト」「完了にする」「進行中に戻す」を用いる。

完了にした後も

- タスク
- 完了履歴
- 種類・受注金額

は保持し、いつでも進行中に戻せる（ステータスは「請求済」に戻る）。

---

# 17. フィルター

プロジェクト詳細画面ではクイックフィルターを実装する。

対象

- すべて
- 今日
- 期限切れ
- 高優先度

# 18. 今回実装しない機能

以下はMVP対象外とする。

- 入金管理（入金日・残金・入金ステータス）
- 失注専用ステータス
- 案件別カスタムテンプレートの保存
- サブタスク
- タグ
- ラベル
- 通知
- 繰り返しタスク
- 添付ファイル
- コメント
- カレンダー表示
- カンバン表示
- ガントチャート
- ダークモード
- オフライン対応
- 複数ユーザー対応
- 権限管理

必要になった場合は、MVP完成後に追加を検討する。

---

# 19. 実装時の原則

- 操作回数を最小限にする
- 入力項目を最小限にする
- 一覧性を優先する
- 過剰設計を避ける
- 保守しやすいコードを書く
- 仕様変更は実装前に提案する
